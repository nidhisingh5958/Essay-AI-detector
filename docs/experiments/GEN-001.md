# GEN-001 — Cross-Generator Generalization (Protocol Only, Not Executed)

**Status: DESIGN ONLY, 2026-08-15. NOT executed.** No second generation
model has been downloaded or run. `PRIMARY-DATASET-v1` is **not**
modified by this design or its eventual execution — any new generator's
output belongs to a separate, small, explicitly-scoped dataset.

## Research question

Does EXP-003A's detector (features + frozen logistic regression) learn
characteristics of AI-generated writing that generalize beyond
Qwen2.5-1.5B-Instruct specifically, or is it primarily learning a
Qwen-specific fingerprint?

**Why this matters now**: DEC-010 already flagged this exact gap when
Qwen2.5-1.5B-Instruct was chosen ("hosted API still reserved for a
future held-out generalization test only") and every EXP-003 report so
far has repeated the same scope limitation — this is that deferred test,
finally being designed, not the first time the concern has been raised.

## A. PRIMARY-DATASET-v1 is not modified

The existing 425-sample benchmark, its manifest, and its splits remain
exactly as frozen. Any GEN-001 data is stored separately (proposed:
`data/generated/GEN-001/`), never merged into
`data/generated/PRIMARY-DATASET-v1/`.

## B. Held-out generator principle

```
TRAIN / DEVELOP  →  existing human + Qwen2.5-1.5B-Instruct data
                     (PRIMARY-DATASET-v1's train+validation splits;
                     EXP-003A's already-frozen model — not refit)

HELD-OUT         →  new generator's output, used ONLY for evaluation
```

The already-frozen EXP-003A model (scaler, `C`, threshold — all fixed
and documented in reports/EXP-003A.md's reproducibility section) is
applied unchanged to the new generator's essays. **No refitting, no
threshold re-selection, no feature changes based on the new generator's
data** — that would defeat the purpose of a held-out test by letting
the held-out data influence the model being tested.

## C. Generator selection

**Recommended candidate: Phi-3.5-mini-instruct** (Microsoft), evaluated
against the required documentation below, with two alternatives
considered and their trade-offs stated.

| Criterion | Phi-3.5-mini-instruct (recommended) |
|---|---|
| Model | `microsoft/Phi-3.5-mini-instruct`, ~3.8B parameters, instruction-tuned |
| License | MIT — no usage restriction relevant to this project |
| Accessibility | Free, downloadable via `transformers`/Hugging Face Hub, no API key, no cost |
| Generation method | Same local, teacher-forced-generation pattern already used for Qwen (`scripts/qwen_generate.py`-style wrapper, directly adaptable — same infrastructure, different model weights) |
| Why sufficiently different from Qwen2.5-1.5B-Instruct | Different vendor (Microsoft vs. Alibaba), different training corpus and recipe, different architecture family, ~2.5x parameter count — a genuinely distinct model, not a same-family variant |
| Compute requirements | Comparable to Qwen2.5-1.5B-Instruct's own generation cost (same CPU-based local inference pattern already used throughout this project — EXP-DATA-001 through R4 all ran this way); one-time download (~7-8GB) |
| Reproducibility | Fully reproducible — open weights, deterministic given a fixed seed, no external API dependency or rate limit |

**Alternatives considered**:

- **A different-size Qwen variant (e.g. Qwen2.5-7B-Instruct)** —
  **rejected as insufficiently different**: same vendor, same training
  recipe/family, same tokenizer lineage — a scale test, not a
  cross-generator generalization test. Would answer "does more Qwen
  capacity help," not "does the signal generalize beyond Qwen."
- **A hosted API model (GPT-4o-mini, Claude Haiku, Gemini Flash)** —
  DEC-010's originally-deferred alternative; genuinely the strongest
  test of generalization (maximally different training data/vendor/
  architecture). **Deferred, not rejected**: requires an API key/cost
  (a new dependency and a real, if modest, expense), is less
  reproducible for anyone without their own key, and reopens the
  vendor-lock-in/reproducibility concerns DEC-010 already weighed when
  choosing a local model as primary. Recommended as a **second-phase**
  cross-generator test if Phi-3.5-mini-instruct's result is
  informative enough to justify the added cost/complexity — not
  proposed for this first, small pass.

## D. Scope

**Small, held-out evaluation only — not a second 150-family dataset.**
Proposed: reuse the **same 23 human essays already in
PRIMARY-DATASET-v1's `test` split** (the exact essays EXP-003A's frozen
model was already evaluated against for `human` vs. Qwen `full_ai`) —
their text is already frozen and unmodified; **only their `full_ai`
counterpart is newly generated, using Phi-3.5-mini-instruct instead of
Qwen**, for the same 23 prompts/target lengths. This produces a clean,
directly comparable 46-essay held-out set (23 human — reused, not
regenerated — + 23 new-generator full_ai), the same size as EXP-003A's
own test set, enabling a like-for-like comparison of the frozen model's
accuracy on Qwen's test set vs. this new generator's test set.

**Why this design, not fresh seeds**: reusing the same human essays
isolates the variable under test (which generator produced the AI
essay) rather than introducing new human-essay variance on top of it;
avoids consuming any of PRIMARY-DATASET-v1's remaining unused seed pool
for what is explicitly a small diagnostic, not dataset expansion.

## E. Possible questions and scope for `ai_assisted`

**For `full_ai`** (primary focus of this first pass): does
EXP-003A's frozen detector, trained only on Qwen-generated `full_ai`
essays, correctly classify Phi-3.5-mini-instruct-generated essays as
machine-written?

**For `ai_assisted`**: **deferred, not attempted in this first pass** —
stated explicitly, per instruction to document why rather than force
it. Reasons: (1) `sentence_light_controlled_v2` is a surgical-splice
mechanism requiring the new generator to be plugged into the full QC +
mandatory semantic-review pipeline (DEC-011/DEC-012) — a substantially
larger undertaking than a whole-essay generation pass, not a "small"
addition; (2) EXP-003B's own `ai_assisted` detector is already near-
chance at the essay level and weak-precision at the sentence level
(EXP-003B/B-R1) — testing cross-generator generalization of a signal
that barely exists for the *original* generator is unlikely to be
informative before that underlying signal itself improves. **GEN-001's
first pass is scoped to `full_ai` only**, as the instructions
anticipated as an acceptable outcome.

## F. Interpretation (fixed in advance, not adjusted after seeing results)

- **Strong performance on the held-out generator** (comparable to
  EXP-003A's original ~98–100% test accuracy) → evidence the detector's
  signal (dominated by lexical-diversity/repetition stylometrics per
  EXP-003A §13) generalizes at least to a second, well-resourced
  instruction-tuned model — not proof of universal generalization, but
  real evidence beyond a single-generator result.
- **Large performance collapse** → evidence the current features
  substantially encode a Qwen-specific fingerprint rather than a
  general "machine-written" signal — an important, reportable negative
  result, not a failure of the experiment.
- **Mixed result** (e.g. strong on stylometric features, weak on
  whatever marginal LM contribution exists, or vice versa) → report per
  feature group (reusing EXP-003A's Baseline B/C/primary structure
  applied to the held-out set), identifying which specific signals
  transfer and which don't.

**A good result on Qwen was never generalization evidence on its own —
this is stated as a standing principle, not just for this experiment**:
EXP-003A's reports have consistently scoped its claims to "this
benchmark, this generation model" for exactly this reason.

## Compute/data requirements

- One-time: download Phi-3.5-mini-instruct (~7-8GB, MIT license, no
  cost, no API key).
- Generation: 23 `full_ai` calls, comparable cost to EXP-DATA-001-R4's
  10-seed regression run (minutes, not hours) — extrapolated linearly,
  well within a single session's compute budget.
- Feature extraction: reuses `exp003a_extract_features.py` unchanged
  (same 29-feature pipeline) — seconds.
- Evaluation: applying the already-frozen model — instant.
- No new PRIMARY-DATASET-v1 storage; new data lives in
  `data/generated/GEN-001/`, clearly separated.

## Limitations, stated now

- n=23 for the held-out generator's `full_ai` class is small — any
  result should be read with a confidence interval (Wilson, matching
  this project's existing practice), not a bare percentage.
- A single alternative generator (Phi-3.5-mini-instruct) establishes
  generalization to *that* model, not to "AI-generated text" broadly —
  the same scope-limitation discipline already applied to every prior
  EXP-003 result applies here too, stated in advance.
- `ai_assisted` cross-generator generalization remains untested after
  this first pass (§E) — a real, disclosed gap, not silently ignored.
- Reuses PRIMARY-DATASET-v1's test-split human essays for a *new*
  purpose (a held-out generator comparison) — this does not modify or
  add to PRIMARY-DATASET-v1 itself, but should be documented clearly
  wherever GEN-001 results are reported, so a reader doesn't confuse
  this with a new detector-selection test-set touch (it isn't one —
  the frozen EXP-003A model's parameters are not touched or reselected
  by this evaluation).
