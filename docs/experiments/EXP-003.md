## 2. Mixed-acceptance imbalance — descriptive analysis

Per explicit instruction, this is a **descriptive** analysis using only
non-sensitive variables, to understand — not correct — why `test`'s
`ai_assisted` acceptance rate (16/23 = 69.6%) is lower than `train`'s
(90/105 = 85.7%) and `validation`'s (21/22 = 95.5%). **The test set is
not altered based on this analysis.**

Variables investigated (all non-sensitive: source essay length, target
span length, span position, PERSUADE `prompt_name`, structural QC
outcome type, length ratio) against the 150 generated (not just
included) `sentence_light_controlled_v2` records:

| Variable | Finding |
|---|---|
| Source essay word count | No meaningful difference by split (train 247±65, validation 246±40, test 240±45) |
| Target span word count | No meaningful difference by split (~18–19 words, all splits) |
| Length ratio (actual/target) | Test shows higher variance (std 0.51 vs. train's 0.36) — consistent with 2 of test's 7 non-accepted samples being extreme scope-drift outliers (ratios 2.06, 3.14), but n=7 is too small to call this a systematic pattern rather than a few unlucky draws |
| Span position (`intended_span_index`) | Weak, inconclusive signal: `changed` samples average a later span position (8.1) than `preserved` (5.6) across the FULL dataset, but `test`'s average span position (4.9) is actually *lower* than train/validation's (5.7/5.9) — this would predict fewer, not more, `changed` cases in test, so it does not explain the imbalance |
| PERSUADE `prompt_name` (essay topic) | Real variation exists across topics (0%–25% changed+questionable rate), but no topic is disproportionately responsible for test's specific problem in a way that generalizes — e.g. "Grades for extracurricular activities" shows 92% acceptance in train (23/25) vs. 50% in test (3/6), but the *same* topic shows the *best* acceptance among topics with any test presence in raw count; the topics with the worst overall rates (Distance learning, Phones and driving, 25% each) are small (12 and 8 total) and one of them (Phones and driving) happens to have **zero** samples in test at all |
| QC note types | No distinctive pattern by split — `modification_scope_drift` and `splice_resegmentation_mismatch` occur at similar relative rates in train and test |

**Conclusion**: no variable investigated shows a clear, generalizing
explanation for test's lower acceptance rate. The pattern is most
consistent with **ordinary sampling variance** given the small
per-split, per-topic cell sizes (test has only 23 `ai_assisted` samples
spread across 8 prompt topics — as few as 2 per topic in some cells).
This is reported as the honest finding, not as a defect requiring a fix.
**No resampling, regeneration, or test-set alteration follows from this
analysis.**

## 7. EXP-003A — Human vs. full_ai

**Status: EXECUTED 2026-08-15, exactly per the protocol below. Full
results: [reports/EXP-003A.md](../../reports/EXP-003A.md).** Headline:
stylometric features alone reach ~100% on this benchmark; the LM
instrument added no measurable value. The protocol below is preserved
as-written (it is what was actually followed, not retroactively edited
to match the result).

**Research question**: can the IMPLEMENTED features (§3/4) distinguish
`human` from `full_ai` essays on PRIMARY-DATASET-v1?

**Classes**: `human` (150), `full_ai` (148) — 298 total, essay-level.

**Hypothesis**: not asserted in advance beyond "some signal likely
exists, direction and magnitude unknown" — per explicit instruction not
to hard-code theoretical expectations (e.g. "AI is more predictable")
into labels or hypotheses before measuring.

**Features**: full IMPLEMENTED set (§4), essay-level features only for
this essay-level task (sentence-level features are aggregated to
essay-level statistics already, per feature-inventory.md — no separate
aggregation step invented here beyond what's already computed).

**Model / baselines**: per §5/§6.

**Training procedure**: fit on `train` (per-split counts in §1) with
internal cross-validation for regularization strength (DEC-015). No
test-set access.

**Validation procedure**: model comparison (primary vs. random-forest
comparison, and vs. each baseline) and threshold selection performed on
`validation` only.

**Test procedure**: **single, final evaluation** on `test`, after the
model/threshold are frozen (§10). Not repeated, not used to pick between
model variants.

**Metrics**: accuracy, precision, recall, F1, confusion matrix (§15).
Given class sizes are close to balanced (150 vs. 148) at this pair,
accuracy is reportable but not sufficient alone — F1 and the confusion
matrix are required, per instruction.

**Model-selection rule**: the model/baseline with the best validation
F1 among those compared is carried to test — chosen once, before test is
touched (DEC-015).

**Threshold-selection rule**: default 0.5 unless validation shows a
documented reason to move it (DEC-015); if moved, the reason and the
validation evidence for it are recorded before test is touched.

**Limitations**: `full_ai` was generated by a single model
(Qwen2.5-1.5B-Instruct, DEC-010) — any signal found is a statement about
detecting *this* model's output, not machine-generated text in general
(§19).

## 8. EXP-003B — Human vs. ai_assisted

**Status: EXECUTED 2026-08-15. Full results:
[reports/EXP-003B.md](../../reports/EXP-003B.md).** Headline: essay-level
detection fails (chance-level); sentence-level localization shows real
but imprecise signal (86.7% recall at 17.6% precision on test). The
protocol below is preserved as-written, not retroactively edited.

**Research question**: can the IMPLEMENTED features distinguish `human`
sentences/passages from `sentence_light_controlled_v2`-derived
`ai_assisted` writing — the realistic mixed-writing case the brief
centers on?

**Classes**: `human` (150 essays), `ai_assisted` (127 essays) — 277
essay-level pairs, **plus** a separate sentence-level task (below).

**This is explicitly not treated as merely another binary essay
classifier** — two evaluations, reported separately:

### 8a. Essay-level evaluation
Same protocol shape as EXP-003A (§7): essay-level aggregated features,
same baseline/model/threshold procedure, same train→validation→test
flow, same metrics. Given class sizes are less balanced here (150 vs.
127) than EXP-003A, class-specific metrics (not just aggregate
accuracy) are required, and macro-F1 is reported alongside per-class
F1 (not weighted-only, which could mask the minority class).

### 8b. Sentence-level localization evaluation
Per [DEC-016](../decisions/DEC-016-sentence-localization-evaluation.md):
ground truth is the exact `modified_spans` provenance (never inferred by
similarity). Scope: the 127 `ai_assisted` essays only. Metrics:
sentence-level precision, recall, F1, confusion matrix — reported
**entirely separately** from 8a's essay-level numbers, per-split.

**Limitations**: `ai_assisted` here means specifically
`sentence_light_controlled_v2` — the ONE sub-mechanism approved for the
primary dataset (DEC-011's Strategic Decision). This is not evidence
about `sentence_moderate_controlled_v2` or paragraph-level AI-assistance
detection, which are entirely absent from PRIMARY-DATASET-v1.

## 9. EXP-003C — Three-class (human / full_ai / ai_assisted)

**Status: DESIGN ONLY, 2026-08-15 — full protocol below, informed by
EXP-003A/B/B-R1's completed results. NOT executed.** Per explicit
instruction: the purpose of this experiment is **not** to maximize a
headline accuracy number — it is to determine how the three writing
regimes overlap, particularly where `ai_assisted` is confused with
`human` (expected to be a real problem, given EXP-003B's essay-level
chance-level result) versus with `full_ai` (untested so far).

**Research question**: can the current measurable feature set
distinguish `human`, `full_ai`, and `ai_assisted` within
PRIMARY-DATASET-v1, and specifically — where do the three classes get
confused with each other?

### A. Data

**PRIMARY-DATASET-v1 only, unmodified.** No new generation, no changes
to family assignments, train/validation/test membership, or the
inclusion manifest. **No new feature extraction required**: this
reuses cached essay-level feature vectors already computed and verified
in EXP-003A (`experiments/EXP-003A/features.jsonl`, `human`+`full_ai`)
and EXP-003B (`experiments/EXP-003B/features_essay.jsonl`,
`human`+`ai_assisted`) — the `human` rows are byte-identical between
the two files (both trace to the same deterministic
`extract_features_for_essay` calls), so building the 3-class dataset is
a de-duplicating merge, not new computation.

**Exact class counts by split** (already established, re-stated here
for this specific experiment):

| Split | human | full_ai | ai_assisted | Total |
|---|---|---|---|---|
| train | 105 | 103 | 90 | 298 |
| validation | 22 | 22 | 21 | 65 |
| test | 23 | 23 | 16 | 62 |
| **Total** | **150** | **148** | **127** | **425** |

**Family leakage**: `find_family_split_violations()` will be re-run
against the merged 425-row dataset before use — expected 0, since every
row's split field is already inherited from the same, already-verified
per-family assignment used throughout PRIMARY-DATASET-v1. (Note: a
family with all three categories present has 3 essay-level rows here,
one per category — this is the same one-row-per-generated-sample
structure EXP-003A/B already used, not a new leakage risk.)

### B. Feature groups

Same three groups as EXP-003A/B, no additions: stylometric-only (23),
LM-only (6), combined (29) — per DEC-014, the pre-registered IMPLEMENTED
inventory only. No NLI, no feature-extractor redesign, no new features
introduced because the task is harder.

### C. Model

Same primary model family as DEC-015: **L2-regularized multinomial
logistic regression** (`sklearn.LogisticRegression`/`LogisticRegressionCV`
with native multiclass support — `multi_class="multinomial"`, the
standard extension of the same model, not a different model family).
Random forest remains available as the same secondary, non-preferred
nonlinearity comparison DEC-015 already established (native multiclass
support, no adaptation needed). No model is switched merely to chase a
better score.

### D. Model selection

Identical discipline to EXP-003A/B (DEC-015): fit and develop on TRAIN;
all feature/hyperparameter/decision-rule choices made on VALIDATION;
test touched exactly once, after everything is frozen. **Decision
rule**: `argmax` over the three predicted class probabilities — the
standard multiclass decision, not a per-class tunable threshold. Per-
class threshold tuning is deliberately not introduced for this first
pass (avoids adding complexity the task doesn't yet justify); if
EXP-003C's confusion matrix (§E) shows a specific class pair would
clearly benefit from a tunable decision boundary, that becomes a
documented follow-up, not something retrofit here after seeing results.

### E. Metrics

Accuracy, **macro-F1** (headline, chosen over weighted-F1 specifically
so `ai_assisted` — the smallest, arguably most important class — isn't
downweighted by its size), **weighted-F1** (also reported, not omitted,
per explicit instruction to report both), per-class precision/recall/F1,
full 3×3 confusion matrix, raw counts. Accuracy alone is never reported
as the headline.

**Confusion pairs to examine explicitly, not just read off the matrix
incidentally**:
- **`human` ↔ `ai_assisted`** — expected to be the dominant confusion,
  given EXP-003B's essay-level result was chance-level for this exact
  pair in isolation; the three-class setting is unlikely to resolve
  what the two-class setting could not.
- **`human` ↔ `full_ai`** — expected to be rare, given EXP-003A's
  near-total separation; if this degrades in the three-class setting,
  that itself is a finding (e.g. the model spending "decision capacity"
  distinguishing `ai_assisted` at the cost of the easier pair).
- **`ai_assisted` ↔ `full_ai`** — genuinely untested territory; no
  prior experiment compared these two directly.

### F. Sentence-level question (resolved here, not deferred by assumption)

**Per explicit instruction, this is a real judgment call, made and
justified here — not "not meaningful" by default, and not attempted
without justification either.**

**The provenance DOES support an exact, non-invented 3-class sentence-
level labeling**: every sentence in a `full_ai` essay is machine-authored
by construction (whole-essay generation, DEC-011); every sentence in a
`human` essay is human; every sentence in an `ai_assisted` essay is
`human` except the one exact `modified_spans` target (DEC-016). No
inference or similarity-based labeling would be required — this is not
a "labels don't exist" problem.

**Recommendation: essay-level remains the primary EXP-003C question for
this round; sentence-level 3-class is deferred, not ruled out.**
Reasons, stated plainly:
1. **Comparability**: EXP-003A and EXP-003B's primary (essay-level)
   results are both essay-level; keeping EXP-003C essay-level first
   keeps the three-experiment comparison on the same footing before
   adding a new granularity.
2. **A real, undemonstrated feature-validity question**: several
   stylometric features (`type_token_ratio`, `moving_average_ttr`
   especially) are aggregate measures whose behavior on a single short
   sentence (rather than pooled across an essay) is untested at 3-class
   scope — EXP-003B-R1 already showed real signal from non-length
   sentence-level features in the *binary* `human`-vs-`ai_assisted` case,
   but extending that finding to include `full_ai` sentences (which,
   recall, come from whole-essay generation, not the surgical splice
   mechanism — their individual sentences were never isolated and
   evaluated as a unit before) is a new, untested combination, not a
   trivial extension.
3. **Extreme class imbalance would worsen further**: `ai_assisted`
   sentence-level positives are already a small minority (119 of ~1,578
   in EXP-003B); adding `full_ai` essays' sentences (~13 × 148 ≈ 1,924
   more rows, all machine-labeled) shifts the balance again in a new way
   that would need its own dedicated design, not a mechanical extension
   of EXP-003B's binary setup.

**If EXP-003C's essay-level result raises a specific question sentence-
level granularity could answer** (e.g. "does `ai_assisted` get confused
with `full_ai` because of properties visible only at the sentence
level"), that becomes a targeted follow-up (an "EXP-003C-R1," mirroring
the EXP-003B → EXP-003B-R1 pattern), not something spliced into this
first pass.

### Compute/data requirements

No new generation, no new feature extraction (§A). Modeling cost is a
few `LogisticRegressionCV` fits on ≤298 rows × ≤29 columns and one
random-forest fit — seconds, not minutes, matching EXP-003A/B's
observed runtime. No new dependency.

## 10. Test-set freeze protocol

**Mandatory for EXP-003A/B/C, no exceptions:**

```
TRAIN
  |
  v
model fitting / feature development
  |
  v
VALIDATION
  |
  v
model selection / threshold selection
  |
  v
FREEZE DETECTOR CONFIGURATION
  |
  v
TEST  (single evaluation, after freeze)
  |
  v
final evaluation report
```

`test` is **not** used for: feature selection, model selection,
threshold tuning, hyperparameter tuning, architecture decisions,
repeated debugging, or repeated performance checks of any kind. Test
performance is inspected **exactly once**, after every other decision
(features, model, hyperparameters, threshold) has already been fixed
using only train/validation. This applies independently to EXP-003A,
3B, and 3C — freezing for one does not permit re-opening it while
developing another.

## 13. Dataset-scope limitation (stated explicitly, per instruction)

**PRIMARY-DATASET-v1 is a controlled, provenance-aware benchmark. It is
NOT evidence of universal AI-detection accuracy.** The human corpus
(PERSUADE 2.0) is educational/student persuasive writing, not a
complete representation of real college admissions essays. The
`full_ai`/`ai_assisted` categories were generated by one local model
(Qwen2.5-1.5B-Instruct, DEC-010). Future EXP-003 results must be
described as **"performance on this benchmark,"** never as "accuracy on
all admissions essays" or "accuracy on all AI-generated writing."

## 14. Architectural constraint (DEC-004, restated for this phase)

The detector must never work as: essay → chat model → "Is this AI?" →
verdict. The local LM (`distilgpt2`, DEC-007) is an instrument only —
it produces token log-probabilities, perplexity, and derived statistics
(feature-inventory.md). The classifier (DEC-015) operates on those
quantitative features, plus stylometric features, to produce a
decision. No chat/generative model is in this loop at any stage,
including explanation (DEC-017).

## 15. Metrics (defined before execution, per instruction)

- **EXP-003A/B (binary)**: accuracy, precision, recall, F1 (per class
  and overall), confusion matrix. Accuracy alone is never the headline
  metric.
- **EXP-003C (multiclass)**: macro-F1 as headline (chosen over
  weighted-F1 to avoid downweighting the smaller `ai_assisted` class —
  see §9); per-class F1; full confusion matrix.
- **EXP-003B sentence-localization**: precision, recall, F1, confusion
  matrix — computed and reported **separately** from essay-level
  metrics, never combined into one number.

## 16. Confidence / probability

Per explicit instruction: raw classifier scores are **not** presented as
"probability this text was written by AI" unless the model has actually
been calibrated (e.g. Platt scaling / isotonic regression against
validation, with the calibration method, data, and metrics documented)
and that interpretation is justified by the calibration evidence. Until
calibration is performed and evaluated, output is described as
**"detector score"** or **"evidence strength,"** not a universal
probability claim.

## 17. Three confidently-wrong examples (reserved procedure)

After final, frozen `test` evaluation (not before, and not used to
select examples early): identify at least 3 essays the detector gets
confidently wrong. For each: sample ID, actual class, predicted class,
detector score, relevant feature values, evidence shown to the user,
likely reason for failure, and what limitation it exposes. **Not
cherry-picked toward flattering failures; not hidden.** This procedure
is reserved now; it is not executed until test evaluation actually
happens.

## 18. Reproducibility requirements

Every EXP-003 run must record: PRIMARY-DATASET-v1 version (manifest
path + its content hash or the manifest file itself, unmodified),
exact train/validation/test split membership (already fixed, §1),
feature-extraction code version (git commit), model configuration
(hyperparameters, random seed), preprocessing/scaling/normalization
method (if any), missing-value handling (e.g. how a `None` LM feature
for a context-free first sentence is handled — not left implicit),
training procedure, validation procedure, threshold-selection
procedure, and evaluation metrics. Nothing here is optional or
"assumed obvious" — every one of these must appear in whatever run
report EXP-003 eventually produces.

## 19. Remaining methodological risks (stated now, not discovered later)

- Small dataset (425 essays; as few as 62 in `test`) makes both model
  fitting and threshold selection noisy — any single-run result should
  be read with this in mind, not treated as a stable rate.
- `full_ai`/`ai_assisted` are both single-model artifacts
  (Qwen2.5-1.5B-Instruct) — no generalization claim to other generation
  models follows from this dataset (DEC-010 anticipated a future
  held-out hosted-API test specifically for this reason; not built yet).
- The automated semantic screen's documented miss rate (DEC-012's
  "Third Validation, at Scale") means `ai_assisted`'s ground truth,
  while human-reviewed, still comes from a single reviewer with no
  inter-rater reliability figure — a real, unresolved limitation.
- Feature set (§3/4) is provisional (DEC-006) and has never been
  measured for signal before this experiment — EXP-003A/B/C is that
  first measurement, not a confirmation of an already-known result.
